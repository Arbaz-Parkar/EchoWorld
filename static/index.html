What am I looking at?

Imagine a small game world with a configurable crowd of characters going about their day, walking between a market, a tavern, barracks, and a watchtower. Every time a character moves or changes what it is doing, that update gets written to two different databases at the same time, for two different reasons.

Redis always holds just the current moment: where is this character right now, what are they doing. It is built to answer that instantly, which matters because a real game asks this question every single frame.

MongoDB holds everything that has ever happened, permanently. It is slower to search but it can answer questions Redis never could, like "what was this character doing an hour ago" or "who has ever walked past this spot."

Click any character to see what it remembers. Use Query Lab to ask both databases the same question and compare their answers. Open the Concepts tab any time for plain explanations of the ideas involved. Enter a run seed to repeat a simulation, then compare saved runs side by side.
